# P12: Why did the IMU stream stop for 29 seconds?

## The question

In one 18-minute run, the IMU stream stopped for 29 s while the app kept running ([H14](../findings/sensors.md#h14-the-imu-can-tell-what-the-wearer-is-doing-even-at-1-hz)). How often does this happen, and what causes it?

## Why it matters

An app that reads posture or activity from the IMU will misread a dropout as stillness. If dropouts are common, apps must detect them and wait.

## Steps

1. Run the probe with the dev server, so the log streams to `apps/probe/logs/` ([apps/probe/README.md](../../apps/probe/README.md#run-it-on-your-glasses)).
2. Swipe up to the Sense page. Pick a pace with swipe down, and note it. Leave the IMU on: a tap turns it off, and that shows as a gap too.
3. Leave it running as long as you can, 30 min or more. Go about your day.
4. Keep rough notes of what you did and when: walking, a call, the phone in a pocket, Bluetooth headphones on.
5. Find the gaps in the log. This lists every gap over 5 s between IMU samples:

   ```sh
   awk -F, 'FNR == 1 { p = 0 } $2 == "imu" { if (p && $1 - p > 5000) print FILENAME, p, $1, ($1 - p) / 1000 " s"; p = $1 }' logs/sense-*.csv
   ```

## What to record

- Every gap: its start time, its length, and what you were doing.
- The total run time and the pace.
- The `frame` rows around each gap. Did sprite frames keep going?
- Phone model, OS version, Even app version, glasses firmware.

## What we know so far

- One dropout of 29 s in one 18-minute run, on 2026-10-03.
- The app kept running through it.
- The cause is unknown.
