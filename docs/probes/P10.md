# P10: What does an IMU and a slow animation cost in battery over 30 minutes?

## The question

Take this load: the IMU on, and one 48 x 48 sprite frame every 5 s. How much battery does it use over 30 minutes or more? Does the display stay lit the whole time?

## Why it matters

Companion apps and pets keep the IMU on and animate slowly for a long time. Developers need a battery cost to design for, and to know whether the firmware dims or turns off the display during a long session.

## Steps

1. Start with the glasses battery below 100%. A battery at 100% can read 100% for the whole run.
2. Run the probe with the dev server, so the log streams to `apps/probe/logs/` ([apps/probe/README.md](../../apps/probe/README.md#run-it-on-your-glasses)).
3. Swipe up to the Sense page. The IMU turns on at pace 100. The corner sprite changes frame every 5 s.
4. Wear the glasses. Leave the page running for at least 30 min.
5. Read the `bat` line: it shows the change since the page opened, and the time.
6. Watch whether the display stays lit, and note when it goes dark if it does.
7. Repeat with the IMU off: tap once on the Sense page. Start from a similar battery level.

## What to record

- Battery at the start and the end, and the run time, for both runs.
- The `battery` and `frame` rows from the CSV log.
- Whether the display stayed lit.
- The pace you used.
- Phone model, OS version, Even app version, glasses firmware.

## What we know so far

- One run of 18 min read 100% the whole time, so it gave no answer.
- Over that run, 184 sprite frames went out with 0 failures ([H15](../findings/lifecycle.md#h15-a-qr-sideload-kept-running-for-18-minutes-with-the-iphone-locked)).
