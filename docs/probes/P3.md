# P3: Does a plugin survive a 30-minute phone lock?

## The question

A plugin runs in the Even app's WebView on the phone. When the phone locks for 30 minutes, does the plugin keep running?

## Why it matters

Even's docs say a QR sideload dies when the phone locks. On one iPhone, a sideload ran for 18 min locked ([H15](../findings/lifecycle.md#h15-a-qr-sideload-kept-running-for-18-minutes-with-the-iphone-locked)). Store review locks the phone for 5 min. Apps that run for a long time (timers, companions, readers) need to know where the limit is.

## Steps

1. Run the probe from a QR sideload ([apps/probe/README.md](../../apps/probe/README.md#run-it-on-your-glasses)). A private or beta build is even better: note which one you used.
2. Stay on the main page. Wait for a few heartbeats (`beats` counts up every 5 s).
3. Note the time and the battery level. Lock the phone.
4. Wait 30 min. Wear the glasses or leave them on, as you like, and note which.
5. Unlock the phone. Read the main page.
6. If the probe is gone, open it again. The last line shows how long the last run lived: `prev: up <time>, died ~<clock time>`.

## What to record

- `beats`, `gaps` and `max` from the first line of the main page.
- The `prev` line if the probe restarted.
- The lock time, and whether the glasses were worn.
- Install type: QR sideload, private build or beta build.
- Phone model, OS version, Even app version, glasses firmware.

## What we know so far

- 2026-10-03, iPhone, QR sideload: 18 min locked with no failure. Sprite frames, IMU samples and network posts all kept going ([H15](../findings/lifecycle.md#h15-a-qr-sideload-kept-running-for-18-minutes-with-the-iphone-locked)).
- Nobody has run the full 30 minutes yet.
- Android is untested.
